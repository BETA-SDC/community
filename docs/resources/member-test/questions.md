# SDC 成员规范测试题库

> 本题库根据 `docs/` 下的制度、流程和资源文档整理，用于新成员熟悉 SDC 的基本协作规范。选择题的干扰项刻意设置为接近正确但违反关键细节的表述，使用前建议负责人再按当期培训重点筛选。

## 选择题

### 1. 活动主 Issue 的建立

在 `event-proposal` 仓库中发起一个新活动时，最符合《活动与宣传》流程的第一步是：

A. 先创建活动目录和 `proposal.md`，待负责人确认后再补主 Issue  
B. 创建 `[event]` 主 Issue，说明活动背景、负责人、时间地点、协作成员和关键截止时间  
C. 先拆分海报、报名和场地等 Sub-issue，再由各执行人分别确认活动是否成立  
D. 先在群聊中完成讨论和人员确认，确定活动后再补充 Issue 记录

### 2. 活动主 Issue 应包含的信息

下列哪一组信息最适合放入活动主 Issue？

A. 活动名称、目的背景、预计时间地点形式，以及已经完成确认的执行细节  
B. 活动名称、初步负责人、预计时间地点和报名方式，但暂不写协作人员与截止时间  
C. 活动名称、目的背景、预计时间地点形式、初步负责人、协作人员、关键截止时间和所需材料，但同时附上完整报名原始表  
D. 活动名称、目的背景、预计时间地点形式、初步负责人、协作人员、关键截止时间和所需材料

### 3. Sub-issue 拆分

进入执行阶段后，负责人应该如何处理具体任务？

A. 先把任务集中写在主 Issue 的 checklist 中，等任务明确后再拆 Sub-issue  
B. 只创建一个总任务 Sub-issue，再由宣传负责人在群聊中口头分派其他工作  
C. 把海报、报名表、场地、物资、现场执行等可独立推进的工作拆成 Sub-issue 并 assign 给对应成员  
D. 先完成材料制作，再根据实际工作量倒推 Sub-issue 和负责人

### 4. 海报或宣传物料任务

当活动需要海报时，以下做法最符合规范的是：

A. 先完成海报设计，再在主 Issue 的评论中补充报名链接和投放渠道  
B. 在对应活动主 Issue 下创建海报任务 Sub-issue，说明用途、截止时间、渠道、报名链接、图片需求，并 @ 活动负责人或宣传负责人  
C. 在 `proposal.md` 中记录海报需求，由宣传负责人统一认领，不另建任务 Sub-issue  
D. 先把参考图和二维码作为主 Issue 附件提交，待海报完成后再补充任务说明

### 5. 通知归档的定义

根据《通知归档规范》，通知归档最准确的含义是：

A. 将最终文案保存为活动目录中的 `notification-message.md`，以文件版本作为发送记录  
B. 将发送渠道、发送时间和通知截图记录在主 Issue 评论中，正文可只保留链接  
C. 将通知内容写进 Pull Request 描述，并在 PR 合并后保留该描述作为唯一归档  
D. 将正式发送后的最终版本复制到对应活动主 Issue 下的 `[message]` Sub-issue 中

### 6. 需要归档的通知

下列哪类信息通常需要归档？

A. 只面向报名成功者发送的活动提醒，因为收件范围较小  
B. 面向活动参与者的邮件通知、正式群通知、报名提醒、时间地点变更或公众号宣传文案  
C. 只包含报名链接和截止时间的短消息，因为内容不涉及活动安排  
D. 活动主 Issue 下协作者之间确认文案措辞的讨论消息

### 7. 通知归档标题

一个微信群通知归档 Sub-issue 的标题最符合规范的是：

A. `[message] Group Birthday Ceremony - 微信群通知`  
B. `[message] Group Birthday Ceremony - 微信群通知 - 2026/09/16`  
C. `[message] Group Birthday Ceremony - 微信群通知 - 2026-09-16`  
D. `[message] Group Birthday Ceremony - notice - 2026-09-16`

### 8. 通知归档标签

邮件通知归档类 Sub-issue 建议至少使用哪些标签？

A. `event` + `mail`  
B. `message` + `notification-poster`  
C. `message` + `mail`  
D. `documentation` + `mail`

### 9. Issue 标题通用规则

以下哪条符合 Issue 协作规范？

A. 主 Issue 使用 `[event]`，Sub-issue 可以省略类型前缀，只保留 parent 和任务名称  
B. 涉及日期时统一使用 `YYYY-MM-DD`，但标题中可以用下划线连接 parent 和其他字段  
C. Sub-issue 中 parent、任务、渠道和日期可以按需要排列，分隔符不作统一要求  
D. 所有 Issue 和 Sub-issue 标题都应使用英文半角方括号作为类型前缀

### 10. 分支命名

活动进入执行阶段后，从 Issue 页面创建分支。推荐分支名是：

A. `05-standard-workflow-final`  
B. `两位issue编号-活动短名`，例如 `05-standard-workflow`  
C. `05-standard-workflow`，但由负责人姓名替换 Issue 编号以便识别  
D. `2026-09-05-standard-workflow`，把活动日期作为分支名的固定第一字段

### 11. Pull Request 说明

活动材料准备到可以审核的状态后，PR 描述中最应该说明的是：

A. 关联的 Issue、本次新增或修改的材料，以及“已确认/待确认”信息  
B. 关联的 Issue、本次新增或修改的材料、已确认和待确认信息、是否涉及公开文案、是否需要特别检查关键事项，但不必重复材料路径  
C. 关联的 Issue、本次新增或修改的材料、已确认和待确认信息、是否涉及公开文案、是否需要特别检查关键事项  
D. 只写公开文案和海报预览，时间、地点、预算和报名方式交由主 Issue 自行追踪

### 12. 活动目录命名

系列活动目录 `YYYY-MM-DD-SERIES-两位期数[-specific-topic]` 中，哪一项说法正确？

A. 日期放在最前面，系列代号全大写且稳定，期数使用两位数字，主题使用英文小写和连字符；主题必须包含年份和季节  
B. 日期放在最前面，系列代号全大写且稳定，期数使用两位数字，但主题应使用系列代号的全大写形式  
C. 日期放在最前面，系列代号可以按本期主题调整，期数使用一位或两位数字均可  
D. 日期放在最前面，系列代号全大写且稳定，期数使用两位数字，主题使用英文小写和连字符

### 13. 活动材料文件命名

下列哪组文件名最符合 `event-proposal` 仓库命名规范？

A. `README.md`、`proposal.md`、`poster-information.md`、`notification-message.md`，并将签到表放在活动根目录  
B. `README.md`、`proposal.md`、`poster-information.md`、`notification-message.md`、`sign-in/`，但在文件名中加入日期和活动短名  
C. `README.md`、`proposal.md`、`poster-information.md`、`notification-message.md`，并将多个渠道写进文件名区分  
D. `README.md`、`proposal.md`、`poster-information.md`、`notification-message.md`、`sign-in/`

### 14. 哪些材料适合直接入库

以下哪类材料适合长期保存在 `event-proposal` 仓库中？

A. 活动策划案、海报信息表、通知文案草稿或备份、活动目录说明、签到统计和整理说明，同时保留原始报名表便于复核  
B. 活动策划案、海报信息表、通知文案草稿或备份、活动目录说明、签到统计和整理说明  
C. 活动策划案、海报信息表和最终宣传文案；签到统计应只保存在负责人个人表格中  
D. 活动策划案、海报信息表、活动目录说明，以及未经整理的原始照片、视频和报名截图

### 15. 签到记录放置位置

活动存在报名、签到或需要统计实际到场人数时，签到记录应放在：

### 16. 签到记录 README

`sign-in/README.md` 至少应说明什么？

A. 活动名称、数据来源和最终汇总人数；分类名单和异常情况可由负责人线下说明

### 17. 签到统计口径

A. 特殊标记只需在汇总表中统一解释，报名名单和签到名单可以合并以减少重复

## 判断题

### 1. 活动流程

判断：活动想法不成熟时也可以先创建主 Issue，因为 Issue 的作用之一是给工作一个可追踪入口。

### 2. 正式通知

判断：正式通知已经发送后，只要草稿保存在分支文件里，就不需要再创建 `[message]` Sub-issue。

### 3. 活动照片视频

判断：活动照片和视频应上传到 Beta College Album，不应只留在聊天记录或个人设备中。

### 4. 签到统计

判断：签到记录只需要保存最终到场人数，不需要保存数据来源、分类名单或异常说明。

### 5. 文件命名

判断：活动材料文件名不建议使用 `final`、`new`、`latest`、`修改版` 等状态词。

### 6. Issue 标签

判断：活动主 Issue 至少添加 `event` 标签；任务分配类 Sub-issue 至少添加 `task` 标签。
